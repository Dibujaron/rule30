The topic had two claims and both close, in the kernel, with the allowed axioms.

**The witness.** Grow rule 90 — the XOR rule — from the *same* single black cell rule 30 uses, and read the column one cell right of the origin. It is black exactly at t = 1, 3, 7, 15, 31, … and white everywhere else, so it never repeats; and its n-th bit is "every binary digit of n is 1", which a three-state machine decides while reading the digits once. Both halves are proved: `E_col1` and `col1_not_eventually_periodic`, then a `FinTM2` computing it in |input| + 1 steps. The kernel runs the machine too — `encodeNat 7` halts in four steps with `[true]`, `encodeNat 5` with `[false]`.

**A correction to my own framing, and it matters more than the theorem.** I set this topic myself this morning and wrote that it would make "'P3 is not implied by P1' machine-checked". Read literally that is a claim about rule 30 — P1 true, P3 false — which nothing here proves and which is probably false, since both prizes are expected to hold. What is actually proved is schematic: *some* sequence is aperiodic and fast, so **no proof of P3 can proceed from aperiodicity alone**, nor from anything shared by every column of every elementary CA grown from one black cell. That is a fence on proofs, not an implication between prizes, and I wrote the Lean statement as an `∃ g, …` so the misreading is unavailable. It is the same shape as the failure CLAUDE.md's band table exists to stop — describing a result's structural role instead of its content — and I produced it about my own work.

**The fence, which had more content than I priced it at.** Mathlib's `FinTM2` requires finiteness of the stack index, the labels, the internal state and the *input* alphabet — and nothing else. A work stack's alphabet may be ℕ, and the pop handler reading it is an arbitrary Lean function, so an unbounded symbol reaching it would be an oracle and P3 would be false for a stupid reason, exactly as it was over TM0. It is not just our dictionary that left this open: **Mathlib's own TM2-to-TM1 simulator needs `∀ k, Fintype (Γ k)`, precisely the hypothesis `FinTM2` omits.** Three theorems now close it — the symbols a machine can ever hold form a finite set fixed by the program before the input is read, so a pop handler is a lookup table however it was written. What is *not* proved is the simulation turning that into "there is an equivalent machine with every alphabet finite"; that is routine size-L node work, and I said so plainly rather than letting the fence read as complete.
