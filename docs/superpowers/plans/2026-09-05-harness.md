# Harness v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Gleam dispatcher that proves one seeded Rule 30 lemma end to end: pick the node, run a named Claude Code identity in a guarded subprocess, verify the proof with Lake, and record everything verbatim.

**Architecture:** A BEAM application in `harness/` owns a JSON DAG of theorem statements, a roster of named identities with notebooks, and a run log. A worker is one `claude -p` subprocess behind an Erlang port (already built and verified as `harness/claude.gleam`), driven turn by turn: the dispatcher sends the task, reads the per-turn structured report, verifies with `lake build` plus a `type_of%` check theorem and `#print axioms`, and sends the verifier's output back until the proof is accepted or the budget is spent. Command hooks in a `--settings` file call a local HTTP endpoint so path and command guards live in Gleam.

**Tech Stack:** Gleam 1.17 on Erlang/OTP 29 (`gleam_stdlib`, `gleam_json` 3, `gleam_erlang` 1.3, `gleam_otp` 1.3, `simplifile`, `argv`, `envoy`, `mist` 6, `gleam_http`); Node 22 for the stdio shim; Claude Code CLI 2.1.261; Lean 4.33.1 with Mathlib pinned in `lakefile.lean`.

**Spec:** `docs/superpowers/specs/2026-09-05-harness-design.md` — read it first; this plan argues from it.

## Global Constraints

- Every `claude` invocation runs without `--bare` (bare mode forces API-key billing; the run is on Dib's subscription) and with `--settings` carrying `"enabledPlugins": {"superpowers@claude-plugins-official": false}`.
- Workers may edit exactly one file: their node's `Rule30/Proofs/<Pascal>.lean`. They may run exactly two commands: `lake build …` and `lake env …`. Everything else is denied by the guard.
- Workers never import `Rule30.Statements`. Sorries are permitted only in `Rule30/Prize.lean` and `Rule30/Statements.lean`; a proof file with `sorry` is rejected.
- A proof is accepted only when the check theorem's axioms are a subset of `propext`, `Classical.choice`, `Quot.sound`.
- Nothing an agent writes is summarised. Notebook and journal entries are written verbatim from the worker's report.
- Model ladder: `S` → haiku, sonnet, opus; `M` → sonnet, opus; `L` → opus; `wall` → never dispatched. A new attempt on a stronger model is a fresh session with prior notes in its brief, never a resume.
- Naming: Lean identifiers are `snake_case` theorems, `lowerCamelCase` defs, `UpperCamelCase` types; Gleam modules are `harness/<name>.gleam`; every Gleam public function has a doc comment.
- Windows host. All paths handed to Erlang ports and Node are absolute with backslashes. Gleam cannot symlink `priv/`, so never create a `priv/` directory in `harness/`.
- Commit after every task, on branch `harness`, with the attribution trailer from the session.
- Tests: `cd harness && gleam test`. Lean: `lake build` from the repo root.

  ```gleam
  pub type Attempt { Attempt(identity: String, session_id: String, model: String,

  pub fn get(dag: Dag, id: String) -> Result(Node, Nil)
  pub fn update(dag: Dag, node: Node) -> Dag

  pub fn proof_module(node: Node) -> String      // "Rule30.Proofs.EvolveLeftEdge"
  pub fn proof_path(node: Node) -> String        // "Rule30/Proofs/EvolveLeftEdge.lean"

  pub fn outcome_to_string(o: Outcome) -> String
  ```

Semantics: `is_open_leaf` is `status == Open` and every dep `Proved`. `open_leaves` sorts by `unblocks` descending, then size ascending (`S < M < L < Wall`), then id. `unblocks(dag, id)` counts nodes that list `id` in `deps` and whose other deps are all `Proved`. `served` is every node with status `Proved`. `proof_module` converts `snake_case` id to PascalCase: split on `_`, capitalise each part, join.

JSON shape (spec): statuses as `"open"|"claimed"|"proved"|"blocked"|"abandoned"`; sizes `"S"|"M"|"L"|"wall"`; outcomes `"proved"|"abandoned"|"reduced"|"budget_exhausted"|"rate_limited"|"timed_out"`; `proof_file` and `verified` nullable strings.

```gleam
fn node_decoder() -> decode.Decoder(Node) {
  use id <- decode.field("id", decode.string)
  use region <- decode.field("region", decode.string)
  use lean_name <- decode.field("lean_name", decode.string)
  use description <- decode.field("description", decode.string)
  use deps <- decode.field("deps", decode.list(decode.string))
  use status <- decode.field("status", enum_decoder(status_from_string, "status"))
  use size <- decode.field("size", enum_decoder(size_from_string, "size"))
  use proof_file <- decode.field("proof_file", decode.optional(decode.string))
  use attempts <- decode.field("attempts", decode.list(attempt_decoder()))
  use verified <- decode.field("verified", decode.optional(decode.string))
  decode.success(Node(id:, region:, lean_name:, description:, deps:, status:,
    size:, proof_file:, attempts:, verified:))
}

fn enum_decoder(parse: fn(String) -> Result(a, Nil), name: String) -> decode.Decoder(a) {
  decode.string
  |> decode.then(fn(s) {
    case parse(s) {
      Ok(v) -> decode.success(v)
      Error(_) -> decode.failure(placeholder_for(name), name)
    }
  })
}
```

`decode.failure` needs a placeholder value of the right type; write one small `fn` per enum (e.g. `Open`, `S`, `TimedOut`) instead of a generic `placeholder_for`. `load` reads with `simplifile.read` and maps errors to strings with `simplifile.describe_error`; `save` writes `encode(dag) <> "\n"`.

```erlang
-export([run_cmd/4, find_executable/1]).
run_cmd(Exe, Args, Cwd, TimeoutMs) ->
    Port = open_port({spawn_executable, binary_to_list(Exe)},
                     [{args, [binary_to_list(A) || A <- Args]},
                      {cd, binary_to_list(Cwd)},
                      binary, stream, use_stdio, exit_status, stderr_to_stdout, hide]),
    collect(Port, TimeoutMs, <<>>).
collect(Port, TimeoutMs, Acc) ->
    receive
        {Port, {data, Bin}} -> collect(Port, TimeoutMs, <<Acc/binary, Bin/binary>>);
        {Port, {exit_status, S}} -> {ok, S, Acc}
    after TimeoutMs ->
        catch erlang:port_close(Port),
        {error, <<"timeout">>}
    end.
find_executable(Name) ->
    case os:find_executable(binary_to_list(Name)) of
        false -> {error, nil};
        Path -> {ok, list_to_binary(Path)}
    end.
```

Gleam side decodes `{ok, S, Acc}` via a private type `RunRaw { Ok3(Int, String) | Err(String) }`; simpler is to have the Erlang return `{run, S, Acc}` / `{timeout}` and match a Gleam type `RunRaw { RunOk(status: Int, output: String) | RunTimeout }`. Convert `"timeout"` to `Error("timeout after " <> int.to_string(ms) <> " ms")`. Note `.cmd` shims cannot be spawned by `spawn_executable`; `which("lake")` returns `…\.elan\bin\lake.exe`, which is a real executable.

```lean
/-
# Seed statements

Captain-authored lemmas for the dispatcher to hand out. Every theorem here is
`sorry` on purpose: this file states, `Rule30/Proofs/` proves. A worker never
imports this file; the harness checks a worker's proof against the statement
here with a `type_of%` check theorem, so the two never share a name.

Regions: `P1` is the geometry of the light cone and its edges, where
periodicity provably holds; `P2` is the density bookkeeping behind the
balance conjecture. P3 gets nothing here on purpose (see `Rule30/Prize.lean`).
-/
import Rule30.Basic
import Rule30.Prize

namespace Statements

/-! ## P1 — the geometry of the cone -/

/-- **Outside the light cone, nothing happens.** After `t` steps every cell
farther than `t` from the origin is still white, because information moves at
most one cell per step and everything started white except the origin.

Induction on `t`; the step case unfolds `evolve_succ` and `rule30_eq` and
uses that all three neighbours were outside the cone one step earlier. -/
theorem evolve_eq_false_of_outside_cone (t : ℕ) (i : ℤ) (h : (t : ℤ) < |i|) :
    evolve t i = false := by
  sorry

/-- **The left edge is always black.** The leftmost cell that can be
non-white after `t` steps is at `-t`, and it is black at every `t`: its left
neighbour and itself were white a step earlier and its right neighbour was
the previous edge, so `xor false (false || true) = true`. -/
theorem evolve_left_edge (t : ℕ) : evolve t (-(t : ℤ)) = true := by
  sorry

/-- **The right edge is always black.** Symmetric in position but not in
argument: at `t`, the previous edge is the *left* neighbour, so the new cell
is `xor true (false || false) = true`. -/
theorem evolve_right_edge (t : ℕ) : evolve t (t : ℤ) = true := by
  sorry

/-- **The second diagonal from the left is all black.** The cell one to the
right of the left edge, at `-t` after `t+1` steps. Its left neighbour was
outside the cone, its own previous value was the left edge (black), so
`xor false (true || _) = true`. -/
theorem evolve_left_second_diagonal (t : ℕ) : evolve (t + 1) (-(t : ℤ)) = true := by
  sorry

/-- **The third diagonal from the left is all white.** The cell two to the
right of the left edge, at `-t` after `t+2` steps: its left neighbour was the
edge (black) and its own previous value was the second diagonal (black), so
`xor true (true || _) = false`. Together with the previous two lemmas this
is the first honest evidence that periodicity lives at the edges of rule 30
and is only conjectured to fail at the centre. -/
theorem evolve_left_third_diagonal (t : ℕ) : evolve (t + 2) (-(t : ℤ)) = false := by
  sorry

/-! ## P2 — density bookkeeping -/

/-- The centre column starts black: the initial configuration has exactly one
black cell, at the origin. -/
theorem centerColumn_zero : centerColumn 0 = true := by
  sorry

/-- The density is never negative: it is a count divided by a natural. -/
theorem centerColumnDensity_nonneg (N : ℕ) : 0 ≤ centerColumnDensity N := by
  sorry

/-- The density never exceeds one: the filtered set is a subset of `range N`,
so its cardinality is at most `N`. (At `N = 0` Lean's `0 / 0 = 0`.) -/
theorem centerColumnDensity_le_one (N : ℕ) : centerColumnDensity N ≤ 1 := by
  sorry

/-- **The density recurrence.** Multiplying out the divisions, the count of
black cells among the first `N + 1` equals the count among the first `N`
plus one if cell `N` is black. `Finset.range_succ` and `Finset.filter_insert`
do the work. -/
theorem centerColumnDensity_succ (N : ℕ) :
    centerColumnDensity (N + 1) * ((N + 1 : ℕ) : ℝ) =
      centerColumnDensity N * (N : ℝ) + (if centerColumn N then 1 else 0) := by
  sorry

end Statements
```

- Produces:
  ```gleam
  pub type Verdict {
    Verified(axioms: List(String), output: String)
    ForbiddenImport(line: String)
    ContainsSorry(line: String)
  ```

Algorithm:
1. Read `repo_root/<proof_path>`; if missing → `BuildFailed("no proof file at …")`.
2. Any line whose trimmed form starts with `import Rule30.Statements` → `ForbiddenImport(line)`.
3. Any line containing the token `sorry` outside a `--` comment → `ContainsSorry(line)` (strip everything from `--` to end of line before searching; good enough because block comments are rare in generated proofs).

5. Write `repo_root/harness/build/checks/<id>.lean`:
   ```lean
   import Rule30.Statements
   import <proof_module>
   theorem harness_check : type_of% Statements.<lean_name> := <lean_name>
   #print axioms harness_check
   ```
6. `shell.run(lake, ["env", "lean", check_path], repo_root, 600_000)`; status ≠ 0 → `CheckFailed(output)`.
7. Parse the line `'harness_check' depends on axioms: [a, b]` (or `'harness_check' does not depend on any axioms`); axioms ⊄ `{propext, Classical.choice, Quot.sound}` → `BadAxioms`; else `Verified`.

`verdict_text` for the worker: `Verified` → "VERIFIED. Axioms: …"; others → a one-line label plus the raw output, e.g. "BUILD FAILED. lake build output follows:\n…".

### Task 6: Build lock actor

**Files:**
- Create: `harness/src/harness/lock.gleam`
- Test: `harness/test/lock_test.gleam`

**Interfaces:**
- Produces:
  ```gleam
  pub type Msg { Acquire(reply: Subject(Bool), holder: String) Release(holder: String) }
  pub fn start(auto_release_ms: Int) -> Result(Subject(Msg), actor.StartError)
  pub fn acquire(lock: Subject(Msg), holder: String, timeout_ms: Int) -> Bool
  ```

Semantics: one holder at a time; `Acquire` when free replies `True` immediately; when held, the request is queued and replied to when released; a held lock auto-releases after `auto_release_ms` (use `process.send_after` to self with `Release(holder)`), so a crashed worker cannot wedge the run. `Release` from a non-holder is ignored.

Use `gleam/otp/actor`: `actor.new(state) |> actor.on_message(handle) |> actor.start`, state `#(Option(String), List(#(Subject(Bool), String)))`. `acquire` uses `process.call(lock, timeout_ms, fn(reply) { Acquire(reply, holder) })` wrapped in `process.try_call`-style handling: if `gleam_erlang` 1.3 has only `call` (which panics on timeout), use `process.new_subject()` + `process.send` + `process.receive(subject, timeout_ms)` explicitly.

`decide` reads `hook_event_name`, `tool_name`, `tool_input`:
