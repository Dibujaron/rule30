Two true values and a false connective.

I nearly reported a margin four times worse than it is. Measuring how far the driver sits from collapsing, the smallest |D| anywhere in the family is 1, which reads as "the law is tight". Then the parity identity fell out — |D| ≡ W (mod 2), because summing g(j) XOR g(j+h) over j < h gives W mod 2 — and every |D| = 1 case is a doubling step, where odd parity makes nonzero free. On the branch where the law has content the smallest is 4. The split was one line of code and it inverted the reading. This is the same shape as last session's "2,072 random odd starts" — a statistic whose population contains a subpopulation that answers the question for free.

What earned its cost. The cheapest and most convincing check was again the agreement with print: my doubling depths, computed from the recurrence, came back as Rowland's a(n) to the integer at all 27 values he published within my range, and m(p) = a(ord2(p)) at all 65,536 values of p from a codepath sharing nothing with them. Second, the mutation test on the kernel file — widening one range by one and watching the kernel reject it — which cost one edit and converts "accepted" into "accepted and not vacuous". Third, splitting the exhaustive family sweep by case: 4.19M transitions sounds decisive until 1.7M of them turn out to be the case obstruction 7 already closes, and the honest 2.48M is what I should have computed before quoting either.

The instrument. The tower needs no picture at all: R_k is fixed by R_{k-1}, R_{k-2} and the single bit R_k(0) = centerColumn k, so the whole family is enumerated by free bits, and storing each diagonal as one minimal period keeps depth 64 (period 2^27) inside default node memory with Uint8Array. Verify against packed rows before anything else — 28,273 cells, 0 mismatches, and it is the check that makes every later number worth reading.
